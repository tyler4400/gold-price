# gold-price 项目说明书

## 目标与当前状态

面向公众提供中文金价走势页，方便查看基础金价、国际现货金折算参考和品牌足金饰品价。后续用户可在验证邮箱后设置到价提醒，无需持有黄金或建立投资账户。

**阶段①–③已完成前端壳、本机抓取、D1 迁移与 Worker API。** latest/history 可查询本地持久数据，ingest 支持鉴权、整批校验与防乱序 upsert；前端仍只有标题、说明、空状态卡片、亮暗主题和 GitHub 链接。完整行情页、定时更新及邮件规则仍是后续目标。[现有七张视觉稿](mockups/) 保留作参考，以本文明确的范围与约定为准。

## 页面与交互（阶段④完整实现）

### 布局与视觉

桌面为主，兼顾手机。以 one-ip 的 GitHub Primer 亮暗配色、系统字体、细边框、紧凑圆角为视觉底，金色仅做点缀。桌面中间内容区约 1000px，两侧保留空白 aside 作为未来广告插槽，不显示「广告」文字；手机隐藏两侧，改为单栏，避免横向滚动。

右上角仅两个图标按钮：主题切换、GitHub。GitHub 链接为 `https://github.com/tyler4400/gold-price`，新标签打开。无语言切换、无顶部「订阅」文字按钮、无其它工具图标。主题支持 light / dark / system，localStorage 保存偏好；默认跟随系统，系统外观改变时同步。使用圆形 View Transition 扩散，尊重 prefers-reduced-motion，不支持动画时直接切换；图标具备中文可访问名称和键盘焦点样式。

### 上金所基础金价大卡

固定名称「上金所基础金价 Au99.99」，显示元/克价格、较昨日涨跌额及涨跌幅、数据日期。不能称作「官方数据」。卡内放「设到价提醒」按钮，v1 点击只提示「即将上线」，不弹出可提交邮箱的假表单、不声称订阅成功。

「较昨日」指同一 item 的上一条有数据日期，而非日历昨天；提示中可展示具体比较日期。上涨红色、下跌绿色、持平中性色，同时提供正负号或文字，不只依赖颜色。无前值显示「暂无对比」，不能伪造 0% 或历史价格。

### 国际现货金参考卡

使用新浪 `hf_XAU` 与 `fx_susdcny` 折算人民币元/克：美元/金衡盎司 × 人民币/美元 ÷ 31.1034768。明确标「参考」，展示有效数据日期，解释受汇率与采样时间影响，不与 Au99.99 或品牌零售饰品价混同。任一输入无效时显示暂无数据，不使用常量汇率补齐。

### 历史走势

计划用 ECharts，默认展示 Au99.99 的 30d，提供 7d / 30d / 90d / 365d 切换。横轴为日期，纵轴为元/克；按北京时间的日历区间查询，不把 7d 解释为最近七个有效报价。一天最多一个点，不出现「日内」入口。

仅绘制已存数据；缺失日期不补点或补零，说明曲线只反映已采集日。首次上线尚无历史时显示空状态，而不是画模拟走势。切换区间具有加载、错误、重试反馈。

### 品牌表与基础报价补充

品牌表列为「品牌」「足金饰品价（元/克）」「较昨日涨跌」「更新日期」。八个饰品品牌为中国黄金、六福、周生生、周大福、老凤祥、老庙、周大生、菜百首饰。涨跌使用红涨绿跌、中性持平及正负号；日期按每个 item 单独展示，不能统一伪标今日。

中国黄金的两种价格必须分为两行：

- 「中国黄金·基础金价」放在基础报价补充区域，明确类别是基础金价，不混入「足金饰品价」列。
- 「中国黄金·足金饰品」放在品牌表中；其数据来自 `data.accessories`，不能用 `data.cur` 代替。

品牌名或价格可点击跳到对应来源页，新标签链接带安全属性；表格不设「来源」列，所有来源统一置于页脚。表格单元格空值显示「— / 暂无数据」，单个品牌缺失不影响其它品牌展示。手机保留核心字段并允许行内合理换行，不隐藏日期或改变价格类别。

### 页脚与空状态

页脚统一列明新浪转发的上金所数据、国际金价及汇率、中国黄金、六福、周生生、品牌备用页及链接；国际参考值写明折算方式。来源说明不暗示上金所官方授权或第三方商业转载许可。

首次进入时请求 `/api/latest`、`/api/history`。空库、无对比历史、单源失败、旧数据、网络错误有各自明确提示。请求失败不能显示为「暂无交易」，陈旧数据不能冒充今日价；数据日期与抓取时刻分开。阶段①的全站空状态只说明尚未接入，不发起上述 API 请求。

## 提醒规则（产品约定，实现后置）

- 只盯「上金所基础金价 Au99.99」（`sge_au9999`），不以国际折算价或品牌饰品价触发。
- 用户以后须先验证邮箱；未验证、退订、禁用规则不能发信。
- 可只设低于、只设高于，也可同时设置；至少一个有效正数阈值，同时设置时下限小于上限。价格严格低于下限或高于上限才命中，恰好等于不命中。
- 同一个用户命中后，北京时间同一天最多一封；早晚再次抓取、重试或修改规则不能重复发送。
- 规则存 D1，验证身份后跨设备恢复；localStorage 只用于主题，不是订阅数据库。
- `last_notified_date` 记录成功通知日，发信失败不误记成功；真正接入时配合原子幂等投递避免并发重复。
- 邮件服务商尚未选择，邮箱验证、退订、验证码、身份验证、投递与重试均不属于当前可用能力。v1 入口仅展示「即将上线」。

## 验收标准

### 阶段①：历史交付边界

- 根目录 AGPL-3.0 LICENSE 与包许可证一致；中文 README 明确 one-ip fork 链和改编范围。
- 可以 pnpm install、dev、lint、typecheck、build；严格 TypeScript，`@/` 别名，Tailwind 4。
- 中文首页壳、约 1000px 中栏、桌面两侧空 aside、手机单栏；右上角只有主题和 GitHub 两个图标。
- 主题偏好持久化、跟随系统、圆形 View Transition、减少动态效果回退；GitHub 链接正确并新标签打开。
- Worker 仅本地静态资源与健康检查，D1 仅配置占位；不包含业务 API、SQL、抓取脚本、adapter、单测或 workflow。
- architecture/spec 记录完整后续设计；`docs/mockups/` 原有七张图及其它已有文件不变。

### 阶段②–③：数据与 API（已实现）

- 每源独立解析与失败处理，中国黄金两类价格不混用；新浪 Referer/GB18030、空 POST 的 Content-Length: 0、备用页 HTTPS/GBK 均按约定处理。
- 六福只读内地足金卖出价，周生生只读足金饰品卖出价；品牌备用页按完整行/列精确匹配，拒绝脆弱数字正则。
- 每条记录有来源与日期，关键源全失败任务非 0；有效源可以独立更新，失败源不置零。
- (`date`, `item_key`) upsert；同日早晚只保留一个点，幂等重试不重复入库，不补造缺失日期。
- latest 返回每项最新价及上一有效日期对比；history 四种范围正确处理空值、顺序、缺日和非法参数；ingest 缺失/错误凭据拒绝写入，secret 不泄露。
- D1 三表已由阶段③迁移创建，订阅数据与公开只读 API 隔离，v1 不启用发信。

本地验收：`pnpm build` → `pnpm db:migrate:local` → `pnpm worker:dev`，通过环境变量配置假密钥后 CLI `--upload` 到本地 Worker，查询 latest/history 并验证错误 token 为 401。原有 Node fixture 测试和 Vitest + Miniflare Worker/D1 测试由 `pnpm test` 一起执行。远端 D1 创建、secret 设置与部署仍由维护者自行操作，见 [README](../README.md)。

### 后续阶段：页面与运行

- 大卡价格、涨跌额/幅、日期和卡内提醒占位齐全；国际价明确参考；品牌表正确区分饰品和基础价格，红涨绿跌并有文字/符号。
- 7d / 30d / 90d / 365d 趋势来自真实日数据；空库、无前值、失败及陈旧数据可辨识，无日内或模拟曲线。
- 来源统一页脚，无来源列；品牌或价格点击正确来源，右上角仍仅两个图标。
- schedule 为 01:30 / 08:00 UTC（北京时间 09:30 / 16:00），有 workflow_dispatch；数据不 commit；定时延迟/60 天停用及人工保活步骤明确。
- 页面不承诺准点刷新或邮件投递。「设到价提醒」点击仅提示「即将上线」，不采集邮箱或声称保存成功。
